# 合同条款评审看板

纯前端单页应用（无需构建、联网或后端）。把每一轮合同版本、每个人对每条的改法、未表态的人集中到同一条款下，避免“同一条件三种改法、上一版意见没处理完就进下一版”。

## 运行

浏览器直接打开 `index.html` 即可。数据存于浏览器 localStorage，关闭页面再回来会自动定位到上次没决定的条款；右上角「重置演示」可恢复内置演示数据。

## 九项功能

1. 按版本列意见：条款页用版本页签切换，意见卡片并排展示提意见人、角色、类型（修改/同意/反对）、改法文字与理由。
2. 改法处置：勾选 1 条可采纳，勾选 2 条可合并（合并文字可编辑），也可以都不采纳但必须写理由。
3. 新版本挂起：导入新版本后，老版未处理意见自动挂到原条款“旧版挂起意见”区并标明版本，不串入新版正文；可“提到当前版讨论 / 仅旧版保留 / 作废留痕”。
4. 催办与跳过：对未表态的人可催办，也可先跳过（强制写原因并留痕），导出时仍会显示“未表态（已跳过）”。
5. 前后不一致：同一人两版给出不同改法文本时自动识别，提交评审组裁定以哪次为准，另一次标记不予采用并留痕。
6. 冲突冻结：同条意见完全冲突时条款冻结、禁止定稿，经“去讨论并解冻”形成结论后才能继续。
7. 卡点总览：一键查看合同卡在哪一条、哪个人、什么原因。
8. 断点续办：顶部“接着上次”横幅直达第一个未决定条款。
9. 导出修改对照：V1→当前版逐行 diff、定稿文字与理由、每条的意见处置清单、跳过记录、操作记录；首页强提示全部未闭环项，支持下载 Markdown 或打印/存 PDF。

## 难点处理

- 版本不串：意见带 versionId，固定挂在所属版本的条款上；历史版本页签只读，旧意见只有显式“提到当前版”才进入当前轮。
- 冻结连带：条款可声明依赖（传递依赖、带循环检测）；上游冻结时下游显示“连带卡住”且不能定稿，解冻后自动解除。
- 定稿后回流：已定稿条款再收到意见，原结论先快照进版本留痕再单独回到评审；合同定稿后同理，历史工作不被冲掉。合同定稿前强校验冻结、连带、待裁定、未处理意见与未表态人，只允许“带保留事项定稿”并在导出首页列明。

## 文件

- index.html：页面结构
- styles.css：样式与打印样式
- app.js：全部逻辑与演示数据（5 名成员、2 个版本、6 条条款，覆盖冻结冲突、前后不一致、挂起、催办/跳过等场景）
